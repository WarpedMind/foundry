## 2026-10-19 (Adversarial pass on the auto-load budget check — the one mechanism without one)

Probed check 11 and its loaded-set derivation, the mutation cases behind them, and `foundry.docBudgetDiscipline`. **Eleven findings, all reproduced against isolated fixture trees rather than argued from reading.** Two are fixed here; the rest are reported and open.

**Fixed: the loaded-set parse (F1/F2).** Five shapes made it report a confident wrong total. A hand-rolled loader — `cat A.md B.md`, a helper script, a sibling list file — hit none of the old SKIP heuristic's signals, so a 310 KB injection reported `PASS … 0% (source: default)`. A decoy `DOC_FILES_ARR=` in a `PreToolUse` hook beat the real loader, because the grep ran over the whole file. `head -1` plus break-on-first-file discarded a second SessionStart loader block and any loader in `settings.local.json`. Rewritten: SessionStart-scoped, positional rather than line-based (a minified settings file is one line), every array summed, nothing deduplicated. The SKIP rule stopped guessing — an unaccounted-for SessionStart hook is unknown, with Foundry's own status hook exempt by its `foundry.scaffolded` read, since `foundry-hooks` installs it unconditionally and otherwise every project without a doc loader would carry a standing SKIP. See DECISIONS.md's 2026-10-19 entry.

**Mutation cases: 38 → 47**, and each new one was neuter-tested rather than assumed — reintroduce `head -1`, unscope the grep, restore the `break`, go line-based, drop the exemption, exempt a whole segment instead of each command, delete the SKIP branch, and in every case exactly the matching case failed. Two older assertions were corrected in the same pass: the unparseable-loader fixture had an `echo hookEventName: SessionStart` appended to it so the then-current heuristic would fire, which made it pass against an input built to satisfy the check rather than the shape it claimed to represent; and a new case that passed for a reason other than its label was relabelled to say what actually carries it.

**Re-derived the eight pre-existing cases by neutering their targets, not by re-reading.** Seven are load-bearing. One is not: "an oversized doc outside the loaded set is not a budget finding" asserts the substring `auto-load budget`, which appears in all five branch labels and so asserts nothing — it discriminates only via its exit code, and only because its pad happens to clear the hard ceiling. Demonstrated by making the check measure the wrong set *and* raising the ceiling: the case passes while the audit reports INFO on a set the loader never names.

**Then fixed, after committing the first two.** The glob gap: an unquoted array entry now makes the set *unresolved*, reported as SKIP with its own message, rather than vanishing — expanding it here would mean claiming this script reproduces the hook shell's globbing, which is a bigger and untested claim than the check needs. A quoted glob stays a literal path and lands in "named but absent", and both halves have a case. The non-discriminating assertion, which took two passes: `auto-load budget` asserted nothing, and `0% of the` was *also* wrong because it is a substring of `190% of the` — the case still passed against a mis-measuring implementation whose percentage ended in a zero. Only the neuter test caught that; re-reading would not have. And all four `docBudgetDiscipline` items: a `"not-measurable-yet"` state for SKIP with a transition out of it, the field now handled per-outcome by `foundry-audit`'s own SKILL.md so a plain audit run is a trigger rather than only the on-request freshness check, the `{{ADDITIONAL_RULES}}` instruction replaced with a direct edit (that placeholder is removed at render time, long before this question can be asked), and the ask separated from the act so `"off"` is reachable. Mutation cases 47 → 49.

**Open, and the one item that needs a decision rather than a patch.** The `./CLAUDE.md` double-count turned out to be the opposite of a bug, and the evidence is this session's own SessionStart output: the conversation received CLAUDE.md twice — once as project instructions, once inside the doc-loader hook's `additionalContext`, which begins `=== CLAUDE.md ===`. So the unconditional prepend's dedupe is *under*-reporting, and this repo's true injected set is ~130,800 B (~82% of budget), not the 107,109 B (66%) the audit prints. Removing the dedupe would be truthful, but it shifts the measurement rather than the threshold, and the recorded 303,867 B that calibrated both thresholds was itself a single-count figure — so the two would no longer be measured the same way. Left for a decision, not patched, because quietly re-basing a number the decision log derives twice is the failure that log exists to prevent.

The `./CLAUDE.md` double-count is subtler than first reported and needs a decision rather than a patch: Claude Code loads CLAUDE.md as project instructions *and* the hook cats it, so the unconditional prepend's dedupe may be under-reporting this repo's own set by 21.7 KB — the question is what the true injected figure is, not arithmetic.
